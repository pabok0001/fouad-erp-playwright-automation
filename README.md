# Fouad Al-Khateeb Hospital — UI Automation

Playwright + TypeScript end-to-end tests for the EMSL Hospital Management System
deployed at `https://202.4.101.118:5555` (Blazor Server app).

## Prerequisites

- Node.js LTS (tested with v24) and Git
- VS Code: open the folder and accept the recommended extensions (`.vscode/extensions.json`)
- k6 for performance tests: `winget install GrafanaLabs.k6` (installed: v2.2.0)
- Chromium for Playwright: `npx playwright install chromium`

## Setup

```bash
npm install
cp .env.example .env      # then fill in APP_PASSWORD
```

`.env` keys:

| Key            | Description                                                                             |
| -------------- | --------------------------------------------------------------------------------------- |
| `BASE_URL`     | App root, e.g. `https://202.4.101.118:5555`                                             |
| `APP_USER`     | Login username                                                                          |
| `APP_PASSWORD` | Login password — **wrap in quotes if it contains `#`** (dotenv treats `#` as a comment) |
| `HEADLESS`     | `true` hides the browser window (default `false`)                                       |
| `API_BASE_URL` | REST API root, e.g. `https://202.4.101.118:5556`                                        |
| `API_VERSION`  | Versioned path segment, default `v1`                                                    |

## Running tests

```bash
npm test               # browser visible, tests run one at a time
npm run test:headless  # same, without the browser window (also automatic in CI)
npm run test:e2e       # UI tests only (chromium project)
npm run test:api       # REST API tests only (no browser)
npm run perf:smoke     # k6: 1 user for 30s — safe sanity check
npm run perf:load      # k6: ramp to 10 users for 2m (tune: -- -e VUS=25 -e DURATION=5m)
npm run test:headed    # watch the browser
npm run test:ui        # Playwright UI mode
npm run test:debug     # step through with the inspector
npm run report         # open the last HTML report
npm run codegen        # record a new flow against the live site
npm run typecheck      # tsc for tests + k6 scripts
npm run lint           # ESLint (incl. eslint-plugin-playwright); lint:fix to auto-fix
npm run format         # Prettier; format:check to verify only
```

## Application notes (learned while building the framework)

- Self-signed TLS certificate → `ignoreHTTPSErrors: true` is set globally.
- Login form fields: `input[name="Input.Email"]`, `input[name="Input.Password"]`,
  button **Log In**. Failed login shows an alert _"Invalid login attempt."_
- **Always reach the login page via `/`** (it redirects to
  `/Account/Login?returnUrl=…`). Opening `/Account/Login` directly leaves the
  Blazor form non-interactive on this server.
- Blazor Server keeps a SignalR connection open, so `networkidle` may never
  fire — prefer `waitForURL` / element assertions over `networkidle`.
- Dashboard module tiles are `<button>` elements. Their DOM text is
  mixed-case (CSS uppercases it), so `DashboardPage.module(name)` matches
  case-insensitively.

## Adding tests

1. Create/extend a Page Object in `pages/<module>/` (shared screens go in `pages/common/`).
2. Add a spec under `tests/<area>/`. Specs run with the stored admin session
   by default; add `test.use({ storageState: { cookies: [], origins: [] } })`
   for tests that must start logged out.
3. Run `npm run lint && npm run typecheck && npm test`.

## Patient registration notes

- Flow: `/hospital/newregistration` → **Add New** (`/hospital/patients/new`) →
  fill form → **Confirm Registeration** → dialog _"New Patient SuccessFully
  Save, Patient ID NNNN"_ → **OK**. `PatientRegistrationPage.confirm()` returns the ID.
- Form is MudBlazor. Controls are located by label (`control(label)`), because
  after a select is chosen its `<input>` turns `type=hidden`.
- DOB is readonly; pick via the calendar: toolbar year → year → month → day.
- District/Thana are autocompletes (type, then choose first suggestion).
- ⚠️ Each run creates a **real patient record** on the server.

## API tests

- API: `https://202.4.101.118:5556` (Swagger UI at `/index.html`, spec at
  `/swagger/v1/swagger.json`, ~1,400 operations). A snapshot is in `api/swagger.json`.
- Auth: `POST /api/v1/identity/token` with `{ email: <username>, password }`.
  Other endpoints need **`x-api-key: <data.userApiKey>`**. A Bearer token alone
  returns 401.
- Use the `api` fixture from `fixtures/api.ts` (logs in once per worker):
  ```ts
  import { test, expect } from '../../fixtures/api';
  import { apiPath } from '../../utils/apiAuth';
  test('x', async ({ api }) => {
    const res = await api.get(apiPath('RegRecord/RegNo/26126844'));
    await expect(res).toBeOK();
  });
  ```
- Responses use `{ data, messages, succeeded, errors }`. A missing record comes
  back as **200 with an empty object** (`uhid: 0`), not 404.
- Known issue: `GET /api/identity/User/loggedIn` returns 500 with an API key.

## Performance tests (k6)

- Scripts are TypeScript; k6 v2 runs them directly. Always start them through
  `npm run perf:*`: `perf/run.cjs` passes the `.env` values to k6, finds `k6.exe`
  even when it isn't on PATH, and writes `perf/results/<name>-summary.json`.
- The journey is **read-only**: list the last 7 days of registrations, then open
  one patient by UHID. Login happens once, in `setup()`.
- Smoke baseline (2026-09-24, 1 VU): p95 188 ms, 0% errors.
- Thresholds: error rate < 1%, checks > 99%, p95 < 2 s (smoke). For load,
  GetByRegDates p95 < 3 s and RegNo p95 < 1.5 s.
- ⚠️ `perf:load` puts real traffic on the server. Get the server owner's OK
  first, especially if it is a live hospital system.
